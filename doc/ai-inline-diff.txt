1. OVERVIEW                                      *ai* *ai-inline-diff*

This plugin shows edits proposed by OpenCode, Claude Code, and Antigravity
inside the editor window you are working in. It does not open a side-by-side
diff or a new tab.

It is a personal plugin built for one workflow, the agents running in
terminals inside Neovim on the versions below. Other setups are not tested,
and keys or behavior may change when that workflow does.

The review temporarily replaces an editor window with the proposed file:

- Removed/original lines are virtual lines highlighted with |DiffDelete|.
- Added/proposed lines are highlighted with |DiffAdd|.
- The original buffer is restored after accepting or rejecting the edit.

Claude and Antigravity proposals are editable before acceptance. OpenCode
proposals are read-only because its permission protocol accepts or rejects
the original patch as a whole.

It needs Neovim 0.12 or newer. The plugin never talks to the agents
directly. It hooks into each agent's Neovim plugin, so those plugins must be
installed and set up first:

  Claude Code    coder/claudecode.nvim
  OpenCode       nickjvandyke/opencode.nvim
  Antigravity    McEazy2700/antigravity-cli.nvim

                                                    *ai-inline-diff-versions*
The plugin replaces internal functions of those plugins and listens to
their events, so a new release can break it. Versions in use:

  Neovim                 0.12.5
  Claude Code CLI        2.1.282
  claudecode.nvim        main at 2390c6e (v0.3.0+53)
  OpenCode CLI           2.1.4
  opencode.nvim          main at e7643e9
  Antigravity CLI        agy 1.2.14
  antigravity-cli.nvim   main at 43d0d38

OpenCode 2.x needs opencode.nvim's `main` branch, which has no release yet.
The plugin also reads OpenCode 1.x events, with opencode.nvim v1.0.2.

2. SETUP                                                *ai-inline-diff-setup*

Call the setup function for each agent you use, after that agent plugin's
own setup:

                                                 *ai-inline-diff-setup-claude*
`require("ai_inline_diff").setup_claude()`
    Replaces the diff functions of `claudecode.diff`. Each `openDiff`
    request from Claude Code opens an inline review.

                                               *ai-inline-diff-setup-opencode*
`require("ai_inline_diff").setup_opencode()`
    Listens to the `OpencodeEvent:permission.asked` autocmd. Each `edit`
    permission request for a single file opens an inline review, and the
    answer goes back through `opencode.server`. Both the OpenCode 1.x and
    2.x event shapes are read (`lua/ai_inline_diff/opencode_event.lua`).
    An edit across several files is left to opencode.nvim's own prompt.

    OpenCode only asks when its configuration has `permission.edit =
    "ask"`; otherwise it writes the file before you can review it. OpenCode
    2.x runs one background server and reads its configuration when that
    server starts, so set it in `~/.config/opencode/opencode.jsonc`: >json
      { "permission": { "edit": "ask" } }
<
                                            *ai-inline-diff-setup-antigravity*
`require("ai_inline_diff").setup_antigravity()`
    Replaces `antigravity-cli.diff`. Each diff Antigravity opens becomes an
    inline review.

Two more setup functions are independent of the review:
|ai-inline-diff-terminal| for agent terminals and
|ai-inline-diff-open-location| for showing code from the agent.

3. REVIEWING EDITS                                    *ai-inline-diff-review*
                                                     *ai-inline-diff-mappings*

When a review opens, its window takes focus and the first change is
selected in linewise Visual mode. A change that only removes lines has
nothing to select; the cursor goes to that row in Normal mode.

The following mappings are local to an active inline review buffer. The
ones that accept or reject act on the whole edit, even when a single change
is selected; ALT-Y and ALT-X act on the selected change only. Each one
leaves you in Normal mode, except the ones that select a change.

ALT-A                     Accept the edit. Normal, Visual and Insert mode.
ALT-R                     Reject the edit. Normal, Visual and Insert mode.
ALT-Y                     Keep the selected change and select the next
                          undecided one. Normal, Visual and Insert mode.
ALT-X                     Put the original lines back for the selected
                          change and select the next undecided one. Normal,
                          Visual and Insert mode.
da                        Accept the edit. Normal and Visual mode.
dr                        Reject the edit. Normal and Visual mode.
q                         Reject the edit. Normal and Visual mode.
<Leader>aa                Accept the edit. Normal and Visual mode.
<Leader>ad                Reject the edit. Normal and Visual mode.
ALT-N                     Select the next change. Normal, Visual and Insert
                          mode. Wraps around after the last change.
ALT-P                     Select the previous change. Normal, Visual and
                          Insert mode.
]c                        Select the next change.
[c                        Select the previous change.
:write                    Accept the edit.

After ALT-Y or ALT-X on the last undecided change the review ends by
itself: it is accepted with the kept changes, or rejected when every change
was dropped. Kept changes show a "✓" sign. OpenCode reviews are read-only,
so ALT-Y and ALT-X only show a warning there.

Only edits that the agent sends to Neovim for approval are reviewed. An
edit made by a shell command, such as `sed -i`, goes straight to disk.
`docs/how-an-edit-flows.md` follows one edit through the code, from the
agent to the file on disk.

Only one inline review is active at a time. A new Claude review rejects an
older pending review before it opens. A new OpenCode request is rejected when
another review is active, so its permission request does not remain pending.

4. AGENT COMMANDS                                    *ai-inline-diff-commands*

These commands come from the agent plugins or from this plugin, and act on
the inline review once the matching setup function has run.

:ClaudeCodeDiffAccept     Accept the inline review in the current buffer.
:ClaudeCodeDiffDeny       Reject the inline review in the current buffer.
:ClaudeCodeCloseAllDiffs  Reject every pending Claude inline review.

:AntigravityDiffAccept    Accept the inline review in the current buffer, or
                          the latest Antigravity review.
:AntigravityDiffDeny      Reject the inline review in the current buffer, or
                          the latest Antigravity review.

OpenCode has no command of its own here. Its review is answered with the
mappings in |ai-inline-diff-mappings|.

5. AGENT TERMINALS                                   *ai-inline-diff-terminal*

Call this once in your configuration: >lua
  require("ai_inline_diff").setup_terminal()
<
It applies to every terminal window, not only agent terminals:

- Focusing a terminal enters terminal mode, so you can type right away.
  Terminals whose process has exited stay in Normal mode.
- CTRL-W {cmd} works from terminal mode, e.g. CTRL-W h or CTRL-W w.
  The terminal program no longer receives CTRL-W; use ALT-BACKSPACE to
  delete a word in OpenCode or Claude Code.
- CTRL-H, CTRL-J, CTRL-K and CTRL-L focus the window in that direction.

Both parts can be turned off: >lua
  require("ai_inline_diff").setup_terminal({
    auto_insert = false, -- keep Normal mode when focusing a terminal
    window_keys = false, -- leave CTRL-W and CTRL-H/J/K/L to the terminal
  })
<
Moving the terminal ~
                                                *ai-inline-diff-terminal-move*
Because CTRL-W works from terminal mode, the built-in window moves do too:
|CTRL-W_L| puts the agent on the right, side by side with the code, and
|CTRL-W_J| puts it below.

Scrolling the agent ~
                                              *ai-inline-diff-terminal-scroll*
Claude Code and OpenCode draw the whole screen themselves, so their history
is not in the Neovim terminal buffer and Normal-mode motions cannot scroll
it. Use the agent's own keys from terminal mode:

Claude Code    CTRL-O opens the transcript. In it, j/k scroll a line,
               CTRL-D/CTRL-U half a page, CTRL-F/CTRL-B a page, g/G jump to
               the top or bottom, and q goes back to the prompt. PageUp and
               PageDown work without opening the transcript.
OpenCode       CTRL-ALT-Y/CTRL-ALT-E scroll a line, CTRL-ALT-U/CTRL-ALT-D
               half a page, PageUp/PageDown a page, CTRL-G and CTRL-ALT-G
               jump to the first and last message.

These are the defaults of Claude Code 2.1.282 and OpenCode 2.1.4.

6. SHOWING CODE FROM THE AGENT                  *ai-inline-diff-open-location*

Ask Claude Code or OpenCode to show you something, for example "open the
place where the parser handles comments", and the file appears in your
editor window with those lines highlighted. Focus stays in the agent's
terminal, so you can keep talking while you read.

                                          *ai-inline-diff-open-location-flow*
A request goes through these steps:

1. At startup, `setup_open_location()` prepends the plugin's `bin/` folder
   to $PATH. Terminals opened after that inherit it and can run
   `nvim-open-location` by name. Terminals that were already open cannot.
2. Each agent starts with the instruction file
   `instructions/open-location.md`. Claude Code reads it through
   `--append-system-prompt-file` and OpenCode through the `instructions`
   list in its config. The file tells the agent to run the script when you
   ask to see code, and what to do when the script fails.
3. The agent finds the code the way it always does, by reading and
   searching files, and then runs something like: >sh
     nvim-open-location src/parser.lua:40-72
<
4. Neovim sets |$NVIM| in every terminal it starts to the address of its
   own server. The script makes the path absolute, because the agent's
   working directory can differ from Neovim's, and asks that server to run
   `open_for_remote()` through `nvim --server $NVIM --remote-expr`.
5. Inside Neovim, `location.lua` loads the file and picks a window. It
   prefers one that already shows the file, then the nearest editor window
   in the current tab. It skips a window with a pending review, because
   replacing that buffer would reject the edit, and opens a split beside
   the terminal when no window fits. The cursor goes to the first line,
   centered, and the range is highlighted with |hl-Visual|. The current
   window never changes.
6. The script prints Neovim's reply. It exits with 0 when the range is
   shown, 1 when Neovim refused it (missing file or a line outside the
   file) and 2 on bad arguments or an empty $NVIM. On a failure the agent
   reads the message and fixes the path or the range.

The highlight goes away when you enter Insert mode in that buffer or when
the agent shows another range.

Setup: >lua
  require("ai_inline_diff").setup_open_location()
<
Then give each agent the file returned by
`require("ai_inline_diff").open_location_instructions()`. Claude Code takes
it with `claude --append-system-prompt-file`, OpenCode with `instructions`
in `~/.config/opencode/opencode.jsonc`. The README has a complete example.

You can also call it from Lua:
`require("ai_inline_diff").open_location(path, first, last)`.

7. SAFETY                                              *ai-inline-diff-safety*

An edit to a file whose buffer has unsaved changes waits: the windows
showing that buffer get a winbar notice, and the review opens once the
buffer is saved, discarded with |:edit!|, or undone back to the saved
text. Answering the agent in its own terminal stops the wait. The review
then compares the file on disk with what the agent will write; Claude Code
and OpenCode write what they prepared when they asked, so text saved in the
meantime (format-on-save included) shows as lines the edit would revert.

An edit is not accepted when:

- The target is a symbolic link whose real file has unsaved buffer changes.
- The target file changes on disk while the review is open.
- The target buffer changes or is replaced while the review is open.
- The OpenCode patch cannot be reconstructed safely in the inline review.

Single-file `Add File` patches and standard unified diffs are rendered inline.
Other patch formats remain pending for manual review in the OpenCode terminal.

The OpenCode integration handles paths relative to both the current directory
and ancestor Git roots. This is needed for `apply_patch`, which can report a
path relative to the worktree rather than the Neovim working directory.

8. TROUBLESHOOTING                            *ai-inline-diff-troubleshooting*

The agent changed a file without showing a review ~

1. Check whether the agent used a shell command, such as `sed -i`, instead
   of its edit tool. Those edits are never reviewed; ask the agent to use
   its edit tool.
2. Check that the setup function for that agent ran after the agent
   plugin's own setup (|ai-inline-diff-setup|).
3. For OpenCode, check that `permission.edit` is `"ask"` in
   `~/.config/opencode/opencode.jsonc` and that the OpenCode prompt does
   not display the `auto` indicator. With OpenCode 2.x, run
   `opencode service restart` after changing it, since the background
   server reads its configuration only when it starts.
4. Run `:checkhealth claudecode`, `:checkhealth opencode` or
   `:checkhealth antigravity-cli`.

The message "diff could not be rendered" appears ~

The edit remains pending in the OpenCode terminal. Check |:messages| for the
detailed reason, then accept or reject it there. Supported inline patches
include single-file `Add File`, standard unified diffs (with `git diff`
headers or the `Index:` header OpenCode 2.x writes), consistent common
indentation trimmed by OpenCode, and paths relative to ancestor Git roots.

The review says the edit is stale ~

The target changed after the review opened. Reject the review and ask the
agent to generate a fresh edit.
